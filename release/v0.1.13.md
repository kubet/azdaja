# v0.1.13

## Intel macOS standalone support

The binary installer and published release contract now support all three documented targets:

- macOS arm64;
- macOS x86_64;
- Linux x86_64 with glibc 2.35 or newer.

The Intel macOS binary is built as a genuine `x86_64-apple-darwin` executable, included in `SHA256SUMS`, exercised through the real installer path, and covered by platform-route and dependency-notice checks.

## Safer managed harness integrations

- Jcode permits only narrowly classified Cargo and Rustup setup commands while continuing to deny read-smuggling and unrestricted Rustup execution.
- Claude's managed approval transaction now requires the exact direct-heredoc envelope, resists command and path smuggling, and passes Claude's strict plugin validator.
- Jcode, Claude, Codex, Gemini, and OpenCode installation and doctor paths are validated together.
- The current managed profile is discoverable through each host's public interface.

## Release integrity and publication verification

Release assembly now requires all three platform binaries before producing the five-entry payload manifest. A read-only post-publication verifier checks:

- the deployed installer version and Intel route;
- exact checksum-manifest equality;
- every payload downloaded and checksum-verified from `azdaja.dev`;
- every GitHub release asset;
- every immutable Git tag payload.

The manual `Verify published release` workflow requires an explicit version and cannot mutate repository contents.
The verifier downloads and verifies all five payloads from each public channel.

## Validation

Before publication, run:

```sh
cargo +1.95.0 fmt --all -- --check
cargo +1.95.0 clippy --locked --all-targets --all-features -- -D warnings
cargo +1.95.0 test --all --locked -- --test-threads=1
cargo +1.95.0 package --locked
release/verify-published-release.sh 0.1.13
```

The final verifier command is expected to pass only after the GitHub release, immutable tag, and production site have all been published.
