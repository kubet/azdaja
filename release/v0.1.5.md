# Azdaja v0.1.5

Azdaja v0.1.5 makes the virtual-memory model visible and fixes the installer and activation UX around it.

## Highlights

- A centered Ratatui/Crossterm console now presents a compact local memory nest: route, resident session state, slot pressure, positional map, and recent residents.
- `az list` is the details-on-demand layer in terminals, with actionable full session IDs, lifecycle state, age, resident bytes, and model. Piped output remains the stable raw-ID interface.
- Measured details expose aggregate-only completed-source size, line counts, and byte entropy with an explicit distribution-only caveat. The overview keeps resident session state separate, and unknown model-boundary exposure and coverage remain labelled `unmeasured` rather than rendered as fake zeros.
- Optional observability sidecars exclude source text, paths, hashes, prompts, and responses. Corrupt or unsafe sidecars degrade the metric display without blocking authoritative `load` or `solo` work.
- The integration view distinguishes the host executable being found from the managed Azdaja profile being ready, absent, or in need of repair.
- Curl-bootstrap detection now uses actual executables, so stale directories and missing tools such as Gemini are not reported as installed.
- The interactive installer preselects detected tools, allows explicit absent-tool targets, shows exact write paths before download, asks for a final confirmation, and emits durable download, verification, staging, and write phases.
- Rich raw-key selection has a numbered fallback. `q`, Esc, and Ctrl-C cancel without mutation and restore terminal state.
- Exact installer-owned legacy Jcode configs migrate to the current `jcode-api` and `gpt-5.6-luna` route so the advertised `az doctor` step works. Any customized bytes remain untouched.
- Shell-owned command/config/document paths and Rust-managed integrations now share one commit boundary: failures before integration commit restore every prior surface, while post-commit backup cleanup warns without triggering a shell-only rollback. Multi-target installs prefer Jcode for the standalone route whenever Jcode is selected.
- The managed Jcode route now verifies both bridge layers and safely replaces its own stale API bridge when Jcode's inner daemon has exited after idle, preventing false-ready `BridgeIo` failures. Socketless numeric pidfiles and missing group leaders fail closed instead of authorizing a signal or pidfile overwrite.
- Exact published v0.1.2 through v0.1.4 managed document bundles migrate transactionally to the current notice set. Forged or changed prior markers remain rejected without mutation.
- The Jcode profile now says `MUST invoke` when the user names Azdaja, asks how it works or whether it is available, names the az virtual-memory tool, or requests complete semantic work beyond a safe context. Jcode auto-injection remains semantic, so `/azdaja` is still the deterministic manual route.

## Supported standalone binaries

- Apple Silicon macOS 11+
- x86-64 Linux with glibc 2.35+
