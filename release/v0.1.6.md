# Azdaja v0.1.6

Azdaja v0.1.6 turns the empty resident-status box into a useful, persistent virtual-memory console.

## Highlights

- Bare `az` now prints a compact inline memory snapshot and exits. The optional `az map` command opens the full-screen local console.
- Successful session `FINAL` values and successful `solo` answers create bounded, aggregate-only memories that remain visible after residents are killed or expire.
- Existing v0.1.5 source-load observations remain readable and are honestly labelled as load traces rather than completed memories.
- The memory constellation is a fixed exact-local scatter plot. Horizontal position is byte entropy, vertical position is an absolute source-size band, `●` is selected/newest, `○` is older, and digits are structural-cell collisions.
- The overview shows explicit source texture: zero-order byte entropy `H₀`, zero-order redundancy, nonempty-line density, observed bytes, and recent memory provenance.
- Details add effective byte alphabet and plain caveats. Entropy is never presented as meaning, quality, confidence, or measured compression.
- Live loaded sources appear as transient traces before completion. Failed, interrupted, rejected, load-only, and killed-unfinalized work does not become a durable memory.
- All persisted history remains provider-free and excludes source text, paths, prompts, responses, answers, hashes, semantic labels, and session identifiers.
- Arrow keys browse retained memories when no resident session exists. Wide, narrow, static, and full-screen views share the same data semantics.

## Supported standalone binaries

- Apple Silicon macOS 11+
- x86-64 Linux with glibc 2.35+
