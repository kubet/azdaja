# One-request native primitive compatibility check

Scope: actual public `jev batch` carrying Noul, Choice and Score together, full validated distributions, native usage accounting, durable response and no-key resume. This is a transport/schema compatibility check on a fictional public bug report, not a long-task efficacy, calibration, accuracy or latency comparison.

- One request with three questions. No generative calls, retries or follow-up inference.
- Native job limits: 1 request, 3,000 reported input tokens, 30 seconds. Per-request timeout 20 seconds.
- Request bytes and accepted binary hash are sealed before admission. Output directory and started marker are exclusive.
- Stop at any error or incomplete result. Preserve diagnostic/usage/intent as reported. Never repair an answer or retry the request.
- Success requires one completed native observation, exact three IDs/types, native accepted distributions and Score legend, known input/output accounting, and fresh-process no-key resume with zero new requests and unchanged job bytes.
- Expected descriptive answers are yes / workaround / middle severity level, but they are reported separately. A single illustrative answer is not evidence of general semantic correctness.
- Use existing authorized credential resolution only. Never retain the credential or mutate its attachment.
- All earlier frozen studies and the138-request long-source job remain untouched.
